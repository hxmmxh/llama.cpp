# x64 Q8 multirow signed dot

The CPU tinyBLAS path now uses AVX-VNNI-INT8 signed byte dot products directly when `__AVXVNNIINT8__` is available. This removes the sign transformations preceding the dot products. The existing eight-lane accumulation, block scales, FMA order and output reduction remain. Other targets use the existing unsigned/signed implementation through the helper.

The helper also serves Q4_0, Q5_0 and IQ4_NL tinyBLAS instantiations. It does not change Q4_K/Q6_K repack kernels, the single-token vector-dot path, model quantization or speculative sampling. The existing runtime CPU variant selection controls instruction availability.

Validation on Windows Core Ultra 7 255H used the frozen `93fda8222` release with only its CPU DLL replaced. Each of two candidates passed 1512 scalar-oracle cases across all four template types, M2/M3/M4/M7/M8/M9, channel tails, padded strides, signed -128 values, output canaries and 1/3/12 worker partitions. Maximum absolute error divided by sum of absolute products was 6.11e-8, below the frozen 2e-6 threshold. The changed translation unit also compiled for the older AVX2 fallback.

Three processes per candidate covered fixed histories 128 and 512, ordinary M1, feature M1, M8 all-logits and M8 last-logits controls. All full-logit hashes matched the historical release. The signed-dot candidate was selected; the alternative Q8 2-channel by 4-position tiling did not meet the selection threshold and is not integrated.

| Metric | Historical release | Signed-dot candidate |
| --- | ---: | ---: |
| M8 ms at D128 | 136.476 | 123.484 |
| M8 ms at D512 | 151.087 | 137.955 |
| Q8 draft ms/round | 48.148 | 39.401 |
| DSpark generation tokens/s | 17.862 | 19.344 |

Generation used four GSM8K prompts twice, 512 output limit, Thinking low, target T=1/top_p=.95 and greedy Q8 draft. Full token arrays and proposed/accepted counts matched historical DSpark. Observed generation improvement was 8.3%; draft time fell 18.2%. These comparisons reuse historical measurements, not an interleaved old/new run. Candidate generation processes were 19.061 and 19.635 tokens/s. Historical ordinary generation was 20.148 tokens/s, so this experiment does not establish a net DSpark speedup over ordinary generation.

This repository includes the signed-dot source change. The separately integrated probability sampling/runtime changes are not part of the measured DLL combination. The experimental CPU DLL and all original package hashes are retained in the [experiment](../../experiments/windows-cpu/20261105-141108-ultra-q8-multirow-r2/REPORT.md). [ARM path analysis](../../experiments/windows-cpu/20261105-141108-ultra-q8-multirow-r2/ARM-PATHS.md) separates existing repack/I8MM support from our GEMM8, head-padding and ARGMAX work.
