# x64 Q8 M7/M8 position reuse

The AVX-VNNI-INT8 tinyBLAS path now processes two output channels across four positions, followed by the same channel pair across three or four positions. M7 uses 4+3 and M8 uses 4+4. Keeping the two position groups adjacent reuses the weight pair while limiting live accumulators. The measured kernels have no SIMD stack accesses inside their K loops.

This specialization requires Q8_0 weights and activations, F16C, signed-byte VNNI, and 16 vector registers. It preserves the original eight-lane dot, FMA and reduction order. Odd output channels use the existing tail path. Other types, position counts, and ISA configurations retain their existing dispatch.

The integrated dispatch also requires every worker to receive a channel pair. With `tiles = m / 2` and `duty = ceil(tiles / nth)`, the fast path is enabled only when `(nth - 1) * duty < tiles`. Here `m` is output channels and `nth` is workers. Small or uneven channel counts that leave workers idle retain position-based tiling. All three measured Spark matrix shapes, including the 131072-channel shared head, satisfy the condition at 12 threads.

## Measured candidate

The Core Ultra 7 255H comparison used the same `ce1e5fd2c` runtime for both variants; only the CPU DLL differed. Main model: Spark-X2.6-4B Q4_K_M. Draft: DSpark-Q8_0-backbone. Both use 12 threads; generation uses Thinking low, target T1/P0.95, draft T1/P1, top-k/min-p disabled.

| Metric | Default 2+2+2+1 | reuse43 | Observed change |
| --- | ---: | ---: | ---: |
| M7 shared head | 11.821 ms | 7.707 ms | cost -34.80% |
| D128 target M8 | 105.695 ms | 104.325 ms | cost -1.30% |
| D512 target M8 | 120.747 ms | 118.596 ms | cost -1.78% |
| DSpark generation | 22.7101 tokens/s | 23.8482 tokens/s | throughput +5.01% |
| Draft time per round | 43.4107 ms | 36.0637 ms | cost -16.92% |

Native timing uses four processes per variant, including the predeclared variation repeat. Generation uses four fixed questions, two processes per variant, ABBA order and at most 512 output tokens. All 16 requests have identical complete outputs, proposal/acceptance counts and round counts. M1 shows no clear change; small FFN micro timings vary substantially.

These timings belong to the measured candidate before the additional worker-occupancy guard. The arithmetic helpers and worker partition are byte-identical in this integration, and the measured Spark shapes still select them. This is not a new timing run or evidence for other CPUs, thread counts or matrix shapes. Full configurations and raw samples are in the [paired experiment](../../experiments/windows-cpu/20261105-185743-ultra-q8-default-vs-reuse43/REPORT.md).

## Integration checks

The measured Windows DLL passed 1854 numerical cases, including 252 M1 fallbacks, signed INT8 extremes, strides, canaries and 1/3/12 concurrent workers. Full output snapshots and fixed-forward logits matched the reference. Those numerical results are reused for the unchanged compute helpers.

The integrated source compiles for AVX-VNNI-INT8, ordinary AVX2, AVX512 and AVX512 with VNNIINT8. Another 564 local checks execute the actual dispatch method with instrumented callees across eligible/ineligible ISA and type combinations, small and odd channel counts, worker-occupancy boundaries, and the measured large shapes. A source check confirms that all legacy fallback code matches HEAD and the new arithmetic helpers match the measured candidate byte for byte.

Build logs, compiler arguments, source hashes, and reproducible checks are in the [integration record](../../experiments/windows-cpu/20261105-211516-q8-reuse43-integration/README.md). At that initial integration step, a fresh Windows DLL correctness run was not started because the machine was locked by another experiment; no other task was stopped. The expanded fixture and that built DLL remain in the integration record. Subsequent [combined hotspot validation](cpu-hotspots-20261105.md) and [round-2 validation and repeats](cpu-hotspots-20261106.md) exercised the integrated implementation in full-model runs. No distribution package or remote daily entry point was replaced.
